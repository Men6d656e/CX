### Task 2 — `apps/vite_express_web_mongodb` (project 2)

Full replica with MongoDB, proper auth, richer frontend:

**Backend** (Express, ESM, modular: routes/controllers/models/middleware/utils):
- Mongoose models: `User` (bcryptjs pre-save hash), `Post` (author ref, likes/dislikes arrays, count virtuals).
- Auth: `POST /register`, `POST /login` → bcrypt + JWT (7d) set as **httpOnly SameSite cookie** AND returned as token for **`Authorization: Bearer`** revalidation (`protect` middleware: bearer header first, cookie fallback). `POST /logout`, `GET /me`.
- Posts: public list/detail (author populated, everyone sees everyone's posts), protected create/update/delete (author-only, 403 otherwise), `GET /posts/mine`.
- Like/dislike: per-user toggle endpoints; like removes own dislike and vice versa.
- `MONGODB_URI` + `JWT_SECRET` in `.env` (user adds the real DB URL). Same start/dev split as v1 (prod serves `frontend/dist` at `/`).

**Frontend** (Vite + React + Tailwind v4 + **react-router page routing**):
- Pages: Feed (all posts + 👍/👎 with counts), Login, Register, My Posts, Create, Edit. Protected routes redirect to login; Navbar shows auth state.
- `AuthContext` restores session via `/me`; `api.js` attaches Bearer token; Vite proxy makes dev same-origin.

**Verified** against a local MongoDB: register ✓, login ✓ (cookie + token), me via bearer ✓ and via cookie ✓, feed shows both users' posts ✓, mine ✓, no-token 401 ✓, like/dislike toggle + cross-removal ✓, edit others' post 403 ✓, edit own 200 ✓, delete by owner ✓, cookie logout → cookie me 401 ✓, bad token 401 ✓. Frontend `npm run build` ✓. README written; user still needs to put the real `MONGODB_URI` in `.env`.
