### Task 1b — Why update/delete looked missing

The backend already had `PUT /api/posts/:id` and `DELETE /api/posts/:id`, and
`api.js` already had `updatePost()`/`deletePost()`. The **UI never showed the
buttons**:

1. `PostCard.jsx` decided ownership with `String(post.author.id) ===
   String(user.id)`. `author.id` is a Mongoose **virtual**, and `User.js` had
   no `toJSON: { virtuals: true }` — the populated author JSON was
   `{"_id":…,"name":…,"email":…}` with **no `id`**, so `mine` was always false
   and Edit/Delete never rendered anywhere (verified against the live DB).
2. `FeedPage.jsx` passed no `onDelete`, so even a visible Delete button would
   have been a silent no-op (`onDelete?.(post)`).

### Task 1c — Fixes made (in `apps/vite_express_web_mongodb`)

- `backend/src/models/User.js` — added `toJSON/toObject: { virtuals: true }`,
  so populated `author` now returns `id` alongside `_id`.
- `frontend/src/components/PostCard.jsx` — ownership check now uses
  `post.author._id ?? post.author.id` vs `user.id ?? user._id` (the `_id` is
  always serialized, so this can't break again).
- `frontend/src/pages/FeedPage.jsx` — added `handleDelete` (confirm →
  `api.deletePost` → reload) and passed `onDelete` to `PostCard`, so delete
  works from the feed, not just My Posts.
- Rebuilt the frontend (`npm run build`) so production serves the new bundle
  (`dist/assets/index-CpX8pjNl.js`).

**Verified live against your MongoDB:** register ✓, create ✓, `GET /posts/mine`
returns `author.id` as a string ✓, update title ✓, delete ✓, deleted id → 404 ✓,
another user's token → 403 on update and delete ✓, owner delete → 200 ✓,
production `/` serves the new bundle ✓. Smoke-test users/posts were removed from
the database afterwards.
